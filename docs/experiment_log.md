- 실행 노트북: `notebooks/run_pipeline.ipynb` (v7. 영상 이름만 넣으면 ROI 자동 계산 → tracking_final.json + 확인용 영상, 결과는 pipeline_outputs/v7)

### 2a. 추적기 튜닝 (평가 클립이 아닌 0143 · 0157, 정답 미사용)
- 튜닝 클립 ROI: 평가 클립 ROI를 ORB 특징점 + 유사 변환으로 옮기려 했으나 실패 → 첫 프레임에서 라인 검출로 직접 계산. 0143 `[[270,459],[1880,469],[1919,612],[1919,1079],[119,1079]]`, 0157 `[[0,0],[1675,0],[1761,737],[0,733]]`
- yolo26x 1920 탐지를 한 번 캐시하고 ByteTrack 설정 55개(high×new×buffer×match + v3 설정) 비교
- 정답 없는 지표: 커버율(추적 박스 ÷ 점수 0.5 이상 탐지), ID 쪼개짐(클립별 고유 ID ÷ 프레임당 추적 인원, 가중 평균), 짧은 트랙 비율(15프레임 미만 ID)
- 사전 규칙: 쪼개짐·짧은 트랙이 v3 설정보다 10% 넘게 나빠지지 않는 설정 중 커버율 최대
- 결과: v3 설정 커버율 1.045 / 쪼개짐 1.645 / 짧은 트랙 0.034 → 선택(h0.25_n0.4_b90_m0.9) 1.082 / 1.438 / 0.037. 상위 설정이 모두 match 0.9 → 짝짓기를 느슨하게 한 것이 쪼개짐 개선의 주된 원인

- 팀 정확도가 박스 단위 0.987 → 추적 후 0.922로 낮아짐 (홍익↔국민 각 18건): 추적 ID가 다른 팀 선수로 넘어갈 때 트랙 전체 다수결이 오히려 틀리게 만듦 → 박스별 클래스나 짧은 구간 평균이 나을 수 있음
- conf는 평가셋을 보고 고르지 않고 사전에 정한 0.15 사용. 학습·평가가 같은 경기의 다른 장면이라 일반화는 미확인

### 6a. 추적 · 팀 라벨 안정화

- 팀 라벨 방식 비교 (탐지·추적은 모두 같음 → det F1 0.957, FP 27, FN 15 동일)

| 방식 | 팀 정확도 | 홍익↔국민 오류 | 플레이 구간 ID 수 (0144 / 0156) |

  - 새 정답으로 채점: 세 방식 모두 득점자를 **ID 하나로 끝까지 추적** (0144 #22 100%, 0156 #1 89.5%, 나머지 2칸은 득점자가 보이지만 탐지 박스가 없던 프레임). 예전에 "득점자 경로가 여러 ID로 쪼개진다"던 것은 정답 오류였음

### 7. 선수 위치를 "선 기준 야드"로 (7a · 7b)
목표: 선수 발 위치를 경기장 좌표로 바꿔 전진 야드 · 필드 포지션 같은 경기 스탯을 뽑기.
- **원칙**: 실제 거리(m)를 쓰지 않음. 경기장마다 선 간격 · 규격이 다르고 1야드 표시가 없는 구장이 대부분이므로, **그려진 선에 야드 값을 붙이고 선 사이는 비율로** 셈 (예: 10야드 선과 20야드 선 사이 60% = 16야드). 실제 경기 기록도 선 기준으로 판정함
- 7a: 참조 화면 4장에서 흰 선 자동 검출(HSV 흰색 마스크 → Hough 직선 조각 → 같은 직선끼리 묶기) 후 번호를 붙여 그림으로 제공 → 사람이 선마다 라벨(엔드라인 −10, 골라인 0, 10 · 20 · 30야드, 사이드라인, 해쉬 L/R, 무시)을 붙임
- 7b 첫 시도 (실패): 야드 선 × 폭 선 교차점을 라벨 값(폭은 대학 규칙 해쉬 20 / 33.33)에 그대로 맞춘 호모그래피 → 교차점 오차 1.5~1.75야드, 펴진 그림에서 선이 기울어짐. 이 경기장의 해쉬 간격은 폭의 약 0.19배인데 규칙 값(0.25)을 강제하면서 원근이 비틀린 것
- 7b 수정: 호모그래피는 "야드 선은 가로로, 폭 선은 세로로 곧게"만 맞추고(양 끝 선 2개씩만 라벨 값에 고정, 가운데 선 위치는 자유, scipy least_squares), 라벨 값은 그다음 선 사이 구간 선형 보정으로 붙임. 합성 경기장(해쉬 23 / 30.5, 20야드 선을 19에 그림)에서 그려진 위치를 정확히 찾고 오차 0.01야드 (예전 방식 2.9야드)
